클로드 코드는 어떻게 도는가 + @ 경로 토큰 실험 — 홍섭

한눈에

① Claude Code는 5가지 컨텍스트를 루프로 돌며 일한다.

② 체크포인트는 대화만 / code만 / 둘다 3종으로 되돌린다.

③ @는 필수 아님 — 큰 파일은 @ 빼고 경로만 줘야 토큰 아낀다 (실험으로 확인).

④ 세션 시작 alias cdd/ccd/ccr — 기본은 권한 전부 위임.

1. 5가지 컨텍스트를 루프로 돈다

파일

예시 — "Jira 버그 티켓 하나 고치기"

  1. 에디터 컨텍스트 — 열린 파일·에러 위치 인지
  2. MCP(Atlassian) — Jira 티켓 본문·재현 절차 가져옴
  3. 파일 시스템 — Grep/Read로 관련 코드 추적
  4. 웹 접근 — 쓰는 라이브러리 최신 문서 확인
  5. 터미널 — 테스트 실행 → 실패 로그 → 다시 ③ 파일로

핵심: 한 줄로 끝이 아니라 터미널 결과 보고 다시 파일로 돌아가는 순환(피드백 루프).

실측: 내 환경에 firecrawl·Atlassian·playwright·kanban MCP 실제 연결됨.

2. 체크포인트 3종 — 무엇을 되돌리나

종류복원 대상언제
대화만대화 맥락만코드는 좋은데 대화가 삼천포 → 코드 두고 대화만 되감기
code만코드 변경만계획은 맞는데 코드가 꼬임 → 대화 살리고 코드만 롤백
둘다대화 + 코드접근 자체가 틀림 → 그 시점으로 통째 복원

아직 직접 안 써봄 — 위는 이해용 가정. 발표 후 /rewind 실제로 걸어볼 것.

3. @ 경로 vs 전체 경로 — 토큰 실험

의문: 경로 지정하면 토큰 아낀다는데, 항상 @ 붙여야 하나?
실험: 300줄(≈10,500토큰) 더미 파일로 두 방식 비교.

@경로

제출 즉시 통째 주입

~10,500

토큰 (파일 전체) · 도구 호출 0회

작은 파일엔 왕복 없이 편하고 쌈. 큰 파일엔 토큰 폭증.

경로만 (no @)

필요한 부분만 Read

~175

토큰 (150줄부터 5줄만) · 도구 호출 1회

Claude가 offset/limit로 필요분만 읽음. 큰 파일에서 절약.

결론
  • @ 필수 아님. 경로만 줘도 Claude가 Read로 읽는다.
  • "경로 = 토큰 절약"은 정확히는 본문 통째 붙여넣기 대비 절약.
  • 작은 파일 → @로 바로, 큰 파일 → @ 빼고 경로만.

곁가지: orca 드래그&드롭 시 @ 자동으로 안 붙던 불편이 이 실험의 계기였는데, 큰 파일이면 @ 없는 게 오히려 이득이라 불편 아님.

4. 세션 시작 alias (개인 팁)

기본은 모든 권한 위임. 실측(~/.zshrc): 프롬프트가 아니라 CLI 플래그였다.

alias실제 명령용도
cddclaude --dangerously-skip-permissions새 세션, 권한 전부 주고 시작
ccdclaude -c --permission-mode bypassPermissions직전 세션 이어가기 (가장 많이 씀)
ccrclaude -r --permission-mode bypassPermissions세션 골라서 재개

settings.json의 skipDangerousModePermissionPrompt가 켜져 있어 확인 창도 스킵됨.

정리

  • Claude Code = 5개 컨텍스트를 피드백 루프로 돈다. "한 번 읽고 끝"이 아니다.
  • 체크포인트는 되돌릴 범위(대화/code/둘다)를 고르는 것.
  • @는 편의 기능이지 필수 아님 — 파일 크기로 갈라 쓴다.
  • 권한·세션은 alias로 자동화 (cdd/ccd/ccr).
