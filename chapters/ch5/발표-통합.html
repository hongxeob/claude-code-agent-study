Chapter 5 · 통합 발표

출력 인터페이스

개인 정리본(홍섭·재윤·준호)을 4개 고정 렌즈로 종합

에이전트의 출력 표면 둘 — 무엇을 말하나(출력 스타일) · 지금 어떤 상태인가(상태 표시줄) 출력 스타일 = 대체 ↔ CLAUDE.md = 추가

참여자별 · 원문 보존

홍섭출력 스타일 vs CLAUDE.md, '플러그인 경로'로 말투 성형 (실측)
  • 내장 5종 — draft 3개(default/explanatory/learning)였으나 공식은 +proactive·concise = 5개
  • 출력 스타일 vs CLAUDE.md — 시스템 프롬프트 직접 수정(행동 교체) vs 유저 메시지 append(지식). "어떻게 응답하나" ↔ "무엇을 알아야 하나"
  • 접두사 — #(CLAUDE.md 저장) / !(bash 모드). 이 세션서 실제로 !로 gsw·gl 실행
  • 핵심 실측 — 내 settings엔 outputStyle 없음(=default). 대신 caveman·i-have-adhd·ponytail 플러그인 + SessionStart 훅으로 출력 성형 중 → 말투 성형을 플러그인이 하고 있음
  • 도입 계획 — ~/.claude/output-styles/에 코드작업/이력서/면접 롤플레잉용
재윤두 출력 표면(스타일·상태 표시줄), 바이너리·settings 실측
  • 중심 메시지 — 출력 표면 둘: 출력 스타일(시스템 프롬프트 대체) + 상태 표시줄(stdin JSON→내 스크립트). 둘 다 설정 파일 소유, 방향만 반대
  • 바이너리 실측(v2.1.258) — strings로 5종 이름·설명, keep-coding-instructions(5회), 플러그인 outputStyles 키 확인
  • 안 만들기로 결정 — CLAUDE.md와 목적 중복 / 프로젝트 수준은 팀 시스템 프롬프트 대체 → 모임 합의 사안
  • 상태 표시줄만 실물 — 인라인 원라이너 해부(jq 5필드, fmt_tokens, IJ_ 변수에 IntelliJ Dracula)
  • 프롬프트↔결과 어긋남 — "~는 Mod" 요청 vs "Mod 3" 구현. settings 읽고서야 발견
준호시스템 프롬프트 계층 원리 + 최신 공식문서 diff + 확장
  • 오해 2개 교정 — "CLAUDE.md는 길어지면 희석" ✗(둘 다 맨 앞, 희석은 훅 주입) / "시스템 프롬프트 세션당 1회 전송" ✗(매 턴 재전송, 1회는 조립)
  • 역할 의미론 — system=협상 불가 vs user=밀어낼 수 있음
  • 컴팩션 생존 — 루트 CLAUDE.md는 재주입 생존, 스코프룰·훅 주입은 소실 → "규칙을 수명으로 분류"
  • 함정 — keep-coding-instructions: true 없으면 SWE 지침 제거(경고 없음)
  • 최신 diff — /output-style 제거(v2.1.91), 3→5종, 저장 3곳+플러그인, /clear 필요, 서브에이전트 미적용(fork 예외)
  • 확장 — 출력 스타일 ≠ --json-schema, --bare 없는 -p의 CI 보안, status line

4 렌즈 · 종합

공통

셋 다 짚은 것

  • 출력 스타일 = 시스템 프롬프트 '대체'(행동 교체) vs CLAUDE.md = '추가'(지식)
  • 내장 스타일은 5종 (default·proactive·concise·explanatory·learning) — 셋 다 도달
  • 커스텀 스타일 구조·위치 — ~/.claude/output-styles/·.claude/output-styles/, YAML frontmatter + 본문
  • keep-coding-instructions의 무게 — 홍섭 인지 / 재윤 각주로 파고듦 / 준호 "가장 중요한 함정"

흥미로운 것

인상 깊었던 개념·경험 (누가)

  • 홍섭output-styles 기능 대신 플러그인 + SessionStart 훅 경로로 이미 출력 성형 중
  • 재윤바이너리를 strings로 떠서 5종·keep-coding-instructions·플러그인 키까지 교차검증
  • 재윤상태 표시줄 해부 — IJ_ 변수에 IntelliJ Dracula, 프롬프트↔결과 불일치를 실측으로 발견
  • 준호"CLAUDE.md는 희석된다"를 틀렸다고 교정 + "조립 1회 vs 전송 매턴" 분리
  • 준호출력 스타일 ≠ structured output(--json-schema=디코딩 제약), "스타일로 JSON 강제"는 안티패턴

갈린 관점

같은 걸 다르게 봄

  • 커스텀 스타일 만들까 — 홍섭: 도입 계획(코드/이력서/면접) / 재윤: 만들지 않기로(CLAUDE.md 중복·팀 합의 사안)
  • 말투 바꾸는 경로 — 홍섭: 이미 플러그인 경로 / 재윤·준호: output-style 기능 자체를 분석
  • "SWE 지침 제거"의 확실성 — 준호: 단정("가장 큰 함정") / 재윤: 미확정(각주, 적용 범위 실행검증 안 함)
  • 상태 표시줄 비중 — 재윤 5:5(실물이 상태줄뿐) / 준호 확장 주제 / 홍섭 안 다룸

팀이 더 팔 것

미해결·궁금 (역질문 모음)

  • 홍섭출력 토큰 절약 — 플러그인 경로 vs 커스텀 출력 스타일 뭐가 유리한가
  • 재윤"custom 시 SWE 지침 제거"가 내장 4종에도? / /output-styles 실동작 / statusLineHealthLatches
  • 준호output style을 -p 모드서 쓸 수 있나(문서 명시 없음, 실험) / keep-coding-instructions:false 기본이 합리적인가
  • 팀프로젝트 수준 스타일은 팀 시스템 프롬프트 대체 → 우리 레포에 하나 만들까 말까(합의 안건)
