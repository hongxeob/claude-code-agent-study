# 5장 출력 인터페이스 — 정리본 (홍섭)

> 개인 학습 노트 구조화본. 각 개념마다 **내 실제 클로드 시스템에서 확인한 적용예시**를 붙였다.

## 1. 말투(출력 스타일) 기본값 — 조사 결과 3개 아닌 5개

draft엔 3개(default/explanatory/learning)로 적었지만 공식 문서엔 **5개**:

1. **default** — 기본(소프트웨어 엔지니어링용)
2. **proactive** — 즉시 실행·가정 선호·계획보다 행동
3. **concise** — 결과 우선·preamble/narration 생략·짧은 응답 (v2.1.237+)
4. **explanatory** — 업무 중간에 교육용 "Insights" 제공
5. **learning** — 협력형 학습(Insights + `TODO(human)` 마커로 사용자가 일부 코드 작성)

- 출처: code.claude.com/docs/output-styles.

**적용예시 (실측)**
- 내 `~/.claude/settings.json`엔 `outputStyle` 키가 **없음** → 지금 **default**로 돌고 있음.

## 2. 커스텀 출력 스타일 생성 (output-styles)

- 프로젝트 성격마다 다르게 두면 효과적일 듯: 코드 작업 / 이력서 피드백 / 면접 롤플레잉 등.

**저장 위치·설정법 (조사)**
- User 전역: `~/.claude/output-styles/`, Project: `.claude/output-styles/` (Markdown 파일).
- 파일 형식: YAML frontmatter(`name`, `description`, `keep-coding-instructions`) + 본문 instructions.
- 선택: `/config` → Output style 메뉴, 또는 settings에 `"outputStyle": "이름"` 직접.

**적용예시 (실측) + 도입 계획**
- 내 시스템엔 `~/.claude/output-styles/`도 프로젝트 `.claude/output-styles/`도 **아직 없음.**
- **도입 계획**: `~/.claude/output-styles/`에 프로젝트 성격별로 — **코드작업용 / 이력서 피드백용 / 면접 롤플레잉용** 스타일을 만들어 `/config`로 전환.

## 3. 출력 스타일 vs CLAUDE.md 차이 (조사 확정)

| 구분 | 출력 스타일 | CLAUDE.md |
|---|---|---|
| 로드 방식 | **시스템 프롬프트 직접 수정** | **유저 메시지로 append** |
| 변경 반영 | `/clear`·새 세션 후 | 다음 세션부터 자동 |
| 역할 | **행동/응답 방식 교체** | **지식/규칙/컨텍스트 추가** |

- 한 줄: **출력 스타일 = "어떻게 응답하나"를 바꾼다(행동 교체) / CLAUDE.md = "무엇을 알아야 하나"를 얹는다(지식 추가).**
- 출처: code.claude.com/docs — output-styles.md, memory.md, settings.md.

**적용예시 (실측)**
- 내 CLAUDE.md 계층: global `~/.claude/CLAUDE.md`(OMC·RTK) + `~/.claude/rules/*`(architecture·code-style·git·logging) + 프로젝트 `CLAUDE.md`(스터디 규칙) → 전부 **항상 로드되는 규칙·지식**. 말투를 바꾸는 장치가 아님.
- 즉 지금 내 말투 성형은 CLAUDE.md가 아니라 **플러그인(§5)** 이 하고 있음 → 둘의 역할 분리가 실제로 드러남.

## 4. 빠른 접두사

- `#` : 입력이 **CLAUDE.md 파일에 추가**됨(메모리 저장).
- `!` : **bash 모드**로 진입(명령을 세션에서 바로 실행).

**적용예시 (실측)**
- 이 세션에서 실제로 `!` bash 모드를 여러 번 씀 — `gsw main`, `gl`, `git pull` 등을 프롬프트에 `!`로 실행해 결과를 대화에 바로 넣었음. (draft 설명과 실측 일치)

## 5. 생각 — 토큰 절약 플러그인 vs 커스텀 출력 스타일

- 요즘 출력 토큰을 아끼는 플러그인(`i-have-adhd`, `caveman` 등)이 나오는데:
  - 그런 **플러그인을 쓰는 게** 이점인가,
  - 아니면 그 베이스에 **커스텀 출력 스타일을 만드는 게** 이점인가 — 고민 필요.

**적용예시 (실측)**
- 지금 내 세팅이 바로 이 고민의 실물이다: `enabledPlugins`에 **`caveman`·`i-have-adhd`·`ponytail` 3개 활성** → 출력 성형을 **플러그인(SessionStart 훅으로 규칙 주입) 경로**로 하고 있음. **출력 스타일 기능(output-styles)은 안 씀.**
- → 비교 포인트: 플러그인은 설치·토글이 쉽고 여러 레포에 공유되지만 훅으로 매 세션 규칙이 주입됨. 커스텀 출력 스타일은 프로젝트 성격에 맞춰 말투 자체를 교체. 어느 게 토큰·유지보수에 유리한지가 §5의 열린 질문.

## 역질문 → 확정 (2단계 사람 게이트 완료)

1. **§3 출력 스타일 vs CLAUDE.md** → **공식 조사로 확정** (위 표: 시스템 프롬프트 수정 vs 유저 메시지 append).
2. **블랙박스/화이트박스 대비축** → **플러그인 경로 vs 커스텀 출력 스타일 경로**로 확정. 발표 HTML 좌우 2열 하이라이트.
3. **§5 고민** → **비교만 제시.** "나는 플러그인 경로 사용 중"을 사실로 두고 장단점만. 결론은 안 냄(열린 질문).
4. **커스텀 출력 스타일 도입 계획** → **넣음** (코드작업/이력서/면접 롤플레잉용).

> 발표 자료(발표.html)는 이 확정본을 입력으로 생성.
