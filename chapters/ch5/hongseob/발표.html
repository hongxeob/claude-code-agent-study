한 줄: 출력 스타일 = "어떻게 응답하나"를 바꾼다(행동 교체) / CLAUDE.md = "무엇을 알아야 하나"를 얹는다(지식 추가).

실측

내 CLAUDE.md 계층: global ~/.claude/CLAUDE.md(OMC·RTK) + ~/.claude/rules/*(architecture·code-style·git·logging) + 프로젝트 CLAUDE.md(스터디 규칙) → 전부 항상 로드되는 규칙·지식이지 말투를 바꾸는 장치가 아니다.

즉 지금 내 말투 성형은 CLAUDE.md가 아니라 플러그인(§5)이 하고 있음 → 둘의 역할 분리가 실제로 드러난다.

빠른 접두사

#

입력이 CLAUDE.md 파일에 추가됨(메모리 저장).

!

bash 모드로 진입 — 명령을 세션에서 바로 실행.

실측

이 세션에서 실제로 ! bash 모드를 여러 번 씀 — gsw main, gl, git pull 등을 프롬프트에 !로 실행해 결과를 대화에 바로 넣었다. (draft 설명과 실측 일치)

고민 — 토큰 절약 플러그인 vs 커스텀 출력 스타일

요즘 출력 토큰을 아끼는 플러그인(i-have-adhd, caveman 등)이 나오는데 — 그런 플러그인을 쓰는 게 이점인가, 아니면 그 베이스에 커스텀 출력 스타일을 만드는 게 이점인가. 결론은 안 낸다(열린 질문), 비교만.

실측

지금 내 세팅이 바로 이 고민의 실물이다: enabledPlugins에 caveman·i-have-adhd·ponytail 3개 활성 → 출력 성형을 플러그인(SessionStart 훅으로 규칙 주입) 경로로 하고 있음. 출력 스타일 기능(output-styles)은 안 씀.

→ 비교 포인트: 플러그인은 설치·토글이 쉽고 여러 레포에 공유되지만 훅으로 매 세션 규칙이 주입된다. 커스텀 출력 스타일은 프로젝트 성격에 맞춰 말투 자체를 교체한다. 어느 게 토큰·유지보수에 유리한지가 열린 질문.

정리

  • 말투를 바꾸는 두 길 — 플러그인(훅 주입) vs 커스텀 출력 스타일(시스템 프롬프트 교체) — 이 대비가 이 장의 핵심.
  • 공식 출력 스타일은 5종(default/proactive/concise/explanatory/learning), 지금 내 설정은 default.
  • 출력 스타일 = 행동 교체 / CLAUDE.md = 지식 추가 — 역할이 다르다. 내 말투 성형은 실제로는 플러그인이 담당.
  • 빠른 접두사 — #은 CLAUDE.md 추가, !는 bash 모드(이 세션서 실사용).
  • 토큰 절약 플러그인 vs 커스텀 출력 스타일 — 결론은 열어둔다. 지금 내 세팅은 플러그인 경로(caveman·i-have-adhd·ponytail).
  • 도입 계획: 코드작업/이력서/면접 롤플레잉용 커스텀 출력 스타일을 만들어 실험해볼 것.
