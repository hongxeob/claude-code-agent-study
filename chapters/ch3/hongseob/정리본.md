# 3장 에이전트 스킬 — 정리본 (홍섭)

> 개인 학습 노트 구조화본. 각 개념마다 **내 실제 클로드 시스템에서 확인한 적용예시**를 붙였다.

## 1. 커맨드 vs 스킬

- **책 정리**: 커맨드는 `/슬래시`로 사람이 **직접 호출·선택**한다. 스킬은 **자연어**로 말했을 때 클로드가 상황을 파악해 **알아서** 사용한다.
- **통합의 실체 = 호출 방식 통합** (확정): 이제 둘 다 **같은 SKILL.md 포맷**을 쓰고, `/슬래시` 직접 호출과 자연어 자동 발동을 **양쪽 다** 지원한다. 성격은 frontmatter의 `disable-model-invocation` 유무로 갈린다(있으면 자동 발동 차단 = 커맨드 성격).

**적용예시 (실측)**
- 커맨드형: nova-workflow의 `commit`, `pr`, `handoff` 스킬은 frontmatter에 `disable-model-invocation`(모델 자동호출 차단) + `argument-hint`가 있음 → `/commit` 식으로 사람이 직접 부르는 커맨드 성격.
- 스킬형(자연어 자동 발동): `humanize-korean`처럼 description에 트리거 문구를 잔뜩 넣어 "AI 티 없애줘"라고만 해도 클로드가 골라 씀.
- → 발표 핵심 대비축: **커맨드(화이트박스: 사람이 직접 지정·제어) vs 스킬(블랙박스: 클로드가 자동 선택)**. 좌우 2열로 시각화.

## 2. 스킬 유형 — 로컬 / 프로젝트 / 팀

**적용예시 (실측)**
- **로컬**: `~/.claude/skills/*` — 개인 전역 스킬 (예: `humanize-korean`, `commit-push-pr`).
- **프로젝트**: 이 레포 `.claude/skills/*` — `pre-chapter-prep`, `mid-study-wrapup` 등 스터디 공용.
- **팀(배포)**: 회사 개발팀에 만들어 제공한 [nova-workflow](https://github.com/mediquitous-dev/nova-workflow) 플러그인 — `nova-api-planner`, `pr`, `commit` 등 18개 스킬을 마켓플레이스로 배포.
- → 발표 때 nova-workflow를 "팀 배포 스킬" 실사례로 짧게 소개.

## 3. SKILL.md 구조

### name 규칙 — 동명사? (조사 결과: 강제 규칙 아님)
- 책: name은 동명사 형태로 짓는다.
- **공식 문서 확인** (code.claude.com/docs/skills): "동명사(gerund) 형태" 규칙은 **공식에 없음**. 공식 예제는 kebab-case일 뿐 형식 강제 없음. 게다가 `name`은 **디스플레이 라벨**이고, 실제 커맨드명은 **디렉토리 이름**에서 온다(plugin 스킬 제외).
- **결론**: 동명사는 강제가 아니라 **관례/가독성 권장**. 동사형(`commit`, `pr`, `handoff`)도 **규칙 위반 아님** — 커맨드 성격엔 오히려 자연스럽다.
- **실측**: 내 스킬 대부분 명사구/kebab(`ab-test-setup`, `humanize-korean`), nova 커맨드형은 동사형(`commit`, `pr`) → 둘 다 정상.

### 분량 — 200줄 이내 (SRP)
- 책: 200줄 이내 권장 = SOLID의 SRP.
- **실측**: `pre-chapter-prep` 66줄, `nova-api-planner` 68줄 → 양호.
- **초과 사례**: `humanize-korean` 257줄 → 오케스트레이터라 길어짐. 리팩터 후보.

### 지원 파일 — reference / script / template
- 책: `reference/`, `script/`, `template/` 지원 파일을 잘 안 썼는데 중요해 보임.
- **책 권고 — 폴더별 역할**:
  - `references/`: 자주 안 읽는 상세 참고 지식. 본문에서 빼고 **필요할 때만 로드** → 평소 토큰 절약.
  - `scripts/`: 반복 로직은 코드로. 실행해 **결과만 컨텍스트에 남긴다**(로직 전문 안 읽어도 됨).
  - `templates/`: 산출물 뼈대. 매번 형식 새로 안 만들고 채우기만.
  - 공통: **도메인별 분리, 깊이 1단계까지, 중첩 참조 금지**.
- **실측 (내 시스템)**:
  - `references/` + `evals/`: 내 마케팅 스킬 대부분이 이 구조 (예: `seo-audit`, `copywriting`).
  - `scripts/`, `templates/`: 개별 SKILL 폴더 안이 아니라 **nova-workflow 플러그인 루트**에 존재. 개별 스킬 안에 `scripts/`를 둔 건 `admin-guide-writer` 하나뿐.
  - → 내 스킬은 아직 **references 위주, script/template 활용은 약함**. 도입 여지 있음.

### context / agent — 컨텍스트 격리 (조사 결과: 실체 확인)
- 책: `context.fork` 처음 접함. agent 옵션 3가지 정리·소개 + 적절/부적절 비교 필요.
- **공식 문서 확인**: 실제 frontmatter 필드는 3개.
  - `context: fork` — 포크된 **서브에이전트**에서 실행(메인 컨텍스트 격리).
  - `agent` — 쓸 서브에이전트 타입 지정. **built-in 3옵션**: `Explore`(읽기전용·작은 컨텍스트·코드탐색/리서치) / `Plan`(계획 수립) / `general-purpose`(기본값·전체 도구). 생략 시 `general-purpose`.
  - `background` — `true`(기본)면 백그라운드 실행, `false`면 결과 대기.
- **적절**: HTML 생성·대량 검색·리서치처럼 **초점이 좁고 산출물만 필요한** 작업 → 격리해 메인 토큰 절약.
- **부적절**: 메인 대화 맥락을 계속 참조·왕복해야 하는 작업 → 격리하면 컨텍스트가 끊긴다.
- **실측 (내 시스템)**: 내 SKILL.md frontmatter 키는 `name`, `description`, `metadata`, `disable-model-invocation`, `argument-hint`, `allowed-tools`뿐 — **`context`/`agent`/`background` 필드는 아직 안 씀.**
- **도입 후보**: `pre-chapter-prep`이 이미 3단계 HTML 생성을 "서브에이전트 위임 가능"이라 명시 → 여기에 `context: fork` + `agent: general-purpose`를 붙이는 게 첫 적용 지점.

## 4. SKILL.md 토큰 최적화 5원칙

1. **description 압축** — 100토큰 예산 안에서 발견 확률 극대화.
2. **범용 지식 빼기** — 클로드가 이미 아는 건 빼고 프로젝트 고유/비공개 정보만 (50~70% 절감).
3. **지원 파일 도메인별 분리, 깊이 1단계까지** — 중첩 참조 금지.
4. **예시는 본문에 1~2개, 나머지는 EXAMPLES.md로** — 예시가 토큰의 20~50% 차지.
5. **로직은 스크립트로** — 실행 결과만 컨텍스트에 남겨 토큰 급감.

**적용예시 (실측)**: 마케팅 스킬군이 본문은 얇게 두고 `references/`로 분리(3원칙), `evals/`로 예시 격리(4원칙)한 구조 → 5원칙의 실물. 반대로 `humanize-korean` 257줄은 본문 비대 → 개선 대상.

## 5. 스스로 던진 질문 → 답 (조사 확정)

### Q1. E2E API 테스트 스킬화 — 환경변수 주입 설계
- **결론: 스킬화 O. 단 env 값은 스킬에 안 넣는다.** 절차(어떤 env 읽어 → 빌드 → E2E 실행)는 SKILL.md, env 값은 `settings.local.json`으로 분리. 환경 전환은 이 파일만 교체.
- **어디에 정의?** `settings.json`의 **`env` 필드**가 맞다. 스코프 3단계: User(`~/.claude/settings.json`) / Project(`.claude/settings.json`) / Local(`.claude/settings.local.json`). 우선순위 **Local > Project > User**.
- **어떻게 읽나?** `settings.json`의 `env`는 **모든 세션에 자동 적용**되므로 이게 1순위 권장. 비밀·환경별 오버라이드(dev/stage)는 gitignore되는 **`settings.local.json`**에 둔다.
- **권장 패턴**: 필수 env는 `CLAUDE.md`의 "required env vars" 섹션에 문서화 + 값은 `settings.json`(`env`)/`settings.local.json`으로 주입. 스킬 body에서 `.env`를 직접 `source`하는 것도 가능하나 자동 적용되는 `env` 필드가 더 깔끔.
- 출처: code.claude.com/docs — settings.md, best-practices.md.

### Q2. 토큰 15% 모니터링 — 쉽게 보는 법
- **`/context` 커맨드**: "무엇이 컨텍스트 공간을 쓰는지" 시각화. **Skills row**가 스킬 목록 점유 크기를 보여줌.
- **statusline**: 하단 바에 셸 스크립트로 **컨텍스트 사용 바를 상시 표시** 가능(color-coded context bar 예제 존재).
- **15% 확인법**: `/context`의 Skills row ÷ 전체 컨텍스트 윈도우(모델별 200K~400K)로 비교. 참고로 auto-compaction은 스킬당 **첫 5,000토큰 유지**, 재부착 스킬 합산 **25,000토큰 예산**.
- 출처: code.claude.com/docs — how-claude-code-works.md, statusline.md, skills.md.

## 역질문 → 확정 (2단계 사람 게이트 완료)

1. **커맨드·스킬 통합의 실체** → **호출 방식 통합**으로 확정. 같은 SKILL.md 포맷 + `/`·자연어 양쪽 호출, `disable-model-invocation`으로 성격 구분.
2. **name 동명사 규칙** → 조사 결과 **공식 강제 아님**(관례). 실제 커맨드명은 디렉토리명. 동사형도 정상.
3. **context/agent 3옵션** → 조사로 실체 확인(`context:fork`/`agent`/`background`, agent 3옵션 Explore·Plan·general-purpose). **개념 소개 + 도입 후보(pre-chapter-prep HTML 단계)** 둘 다 발표에 포함.
4. **블랙박스/화이트박스 대비축** → **커맨드(화이트박스) vs 스킬(블랙박스)**로 확정. 발표 HTML에 좌우 2열 시각화.
