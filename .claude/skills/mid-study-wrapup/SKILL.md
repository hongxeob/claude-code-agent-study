# study-wrapup — 회의록 → 마지막 10분 회고 베이스

## 회고란 (요약과 다른 점)

**요약**은 "무슨 일이 있었나"에서 멈춘다. **회고는 거기서 두 걸음 더 간다:**

```
사실 (무슨 일)  →  성찰 (그래서 뭘 느꼈나/배웠나)  →  액션 (다음에 뭘 바꿀까)
```

이 스킬은 요약기가 아니라 **거울 + 회고 틀**이다. 말한 걸 되비추되(사실), 그걸 성찰·액션 자리에 배치해 사람이 마지막 10분에 회고하도록 **판을 깔아준다.** 성찰과 액션의 알맹이는 사람이 채운다.

## 플로우 상 위치

1. 각자 10분 발표 (챕터 정리 + 본인 생각) → 30분.
2. Gemini가 발표·토의를 회의록으로 기록.
3. 통합(merge) 끝나면 그 **회의록을 이 스킬에 투입.**
4. 출력(회고 베이스)을 보며 **마지막 10분, 사람이 회고 토의.** ← 회고 자체는 사람이 함.

## 입력

- 그 주 발표·토의를 담은 **Gemini 회의록** (경로 또는 붙여넣기).
- **`📖 스크립트`(전사 발화)를 1순위 근거로** 삼는다. `요약`·`상세정보` 섹션은 보조.
  - 이유: 회의록 요약은 이미 한 번 압축된 것. 그걸 다시 옮기면 **요약의 요약** = 본인 어투·뉘앙스가 죽는다.
- **이전 회고 파일**이 있으면 먼저 읽는다 — `meeting-notes/*-회고.md` 중 직전 주차 것. 지난 Try·액션이 이번에 이행됐는지 점검하려는 것(연속성). 없으면 그 블록은 생략.

## 출력

### 0) 지난 Try 이행 점검 (이전 회고 파일이 있을 때만)
직전 회고의 **Try·액션 아이템**을 한 줄씩 나열하고 이번 회의록 근거로 상태를 표시한다: `✅ 됨 / 🔶 부분 / ❌ 안 됨 / — 언급 없음`. 근거는 이번 스크립트 발화에서만. 이전 회고가 없으면 이 블록 생략.

### 1) 개인 회고 (발언자별) — 발화 기반, 1인 4줄 이내
- **[사실] 오늘 핵심** — 내가 발표·이해한 것 1~2개
- **[성찰] 내 생각·관점** — 내 의견, 바뀌거나 굳어진 생각, 놀란 점
- **[성찰] 걸린 것** — 헷갈렸던·의문·아직 모르는 것 (더 팔 지점)
- **[액션] 다음에 해볼 것** — 해보기로 한 것 1~2개

### 2) 팀 회고 (KPT) — 토의 전체 기반, "스터디 자체"를 되돌아봄
- **Keep (잘된 것)** — 오늘 진행·논의에서 좋았던 것
- **Problem (아쉬운 것)** — 시간·방식·준비에서 걸린 것
- **Try (다음에 바꿀 것)** — 다음 주 개선 액션

### 3) 액션 아이템 — 담당자 + 기한
1)의 `[액션]`과 2)의 `Try`에서 **실제 할 일만** 뽑아 담당자를 붙인다. 다음 회고의 0)에서 이 목록을 그대로 점검한다.
- 형식: `- [ ] [담당자] 할 일 (기한: 있으면)`
- 발화에 담당·기한이 있으면 그대로. 없으면 담당 `(미정)`, 기한 생략. **담당자를 추측해 지정하지 마라.**

### 4) 열린 질문 (다음까지 생각해올 것)
토의 중 **실제로 나온 미해결 질문·의문·"모르겠다"**를 팀 공유거리로 모은다 (개인 `걸린 것`의 팀 버전). 다음 모임 전까지 각자 곱씹을 씨앗.
- **발화에 나온 질문만.** AI가 새 질문을 지어내지 마라 — 그 순간 사고를 대신하는 것. 없으면 비운다.
- 챕터 지식 미해결은 chapter-merge의 "팀이 더 팔 것" 몫. 여기는 **운영·경험** 쪽 열린 질문.

### 5) 확인 질문 1개
애매하게 분류했거나 발화 근거가 약한 항목을 본인/팀에게 되묻는다. **답은 주지 않는다.**

## 규칙 (어기면 회고가 요약으로 죽는다)

1. **스크립트 발화만 재배치.** 회의록 요약 문장을 그대로 옮기지 마라. 추론·미화·"더 나은 생각"으로 채우지 마라.
2. **성찰·액션은 발화에 있을 때만.** 없으면 `(언급 없음)`으로 남긴다 — 빈칸이 곧 "아직 회고 안 한 부분", 마지막 10분에 사람이 채울 신호다.
3. 특히 **[성찰] 내 생각은 AI가 못 채운다.** 발화에 명시적으로 있을 때만 옮긴다.
4. **발언자 분리**: 스크립트에서 화자별(`이홍섭:`, `신재윤:`, `Junho:`)로 모아 배치. 매핑이 애매하면 지어내지 말고 확인 질문으로.
5. KPT는 **스터디 운영**에 대한 것 — 챕터 지식 통합은 chapter-merge 몫이니 여기서 중복하지 마라.
6. 각 불릿 한 줄, 발언자 본인 어투 살린다.
7. **액션 아이템·이행 점검도 발화 근거만.** 담당자·기한·이행 상태를 지어내지 마라 — 근거 없으면 `(미정)`·`— 언급 없음`.

## 예시

입력(회의록 스크립트 발췌):
```
신재윤: 서브에이전트 병렬로 돌리면 빠를 줄 알았는데, 토큰이 두 배로 나가더라고요. 손익을 안 재봤네.
이홍섭: 시간 배분이 좀 아쉬웠어요. 발표가 길어져서 회고가 밀렸음. 다음엔 타이머 딱 끊죠.
```

출력:
```
### 신재윤
- [사실] 오늘 핵심: 서브에이전트 병렬 실행의 토큰 비용
- [성찰] 내 생각·관점: "병렬 = 무조건 이득"인 줄 알았는데 아니었음
- [성찰] 걸린 것: 병렬 손익분기를 안 재봤다 (더 팔 것)
- [액션] 다음에 해볼 것: (언급 없음)

## 팀 회고 (KPT)
- Keep: (언급 없음)
- Problem: 발표가 길어져 회고 시간이 밀림
- Try: 다음엔 발표 타이머를 딱 끊는다

## 액션 아이템
- [ ] [이홍섭] 발표 타이머 딱 끊기 (기한: 다음 모임)
- [ ] [(미정)] 병렬 손익분기 측정

## 열린 질문 (다음까지 생각해올 것)
- 병렬 위임이 토큰 2배를 정말 상쇄하는 손익분기는 어디쯤인가?

확인 질문: 신재윤님 "다음에 해볼 것"이 발화에 없었어요 — 손익분기 측정을 액션으로 둘까요?
```

> 이전 회고가 있었다면 맨 위에 `## 지난 Try 이행 점검` 블록이 붙는다 (예: `- 발표 타이머 딱 끊기 → ✅ 됨`).

## 산출물

- 저장 위치: **`meeting-notes/<회의록과 같은 날짜>-<N주차>-회고.md`** (예: `meeting-notes/2026-07-30-2주차-회고.md`).
- 회의록 바로 옆에 페어로 둔다. 날짜·주차는 그 주 회의록 파일명을 따른다 (추측 금지).
- 저장 전 같은 이름 파일 있으면 덮어쓰기 확인.
