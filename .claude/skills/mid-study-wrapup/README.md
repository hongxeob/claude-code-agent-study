# study-wrapup — 팀원용 안내

스터디 발표·토의를 담은 **Gemini 회의록**을 받아, 마지막 10분 **회고의 베이스**를 만들어주는 스킬.

> 만든 사람: 홍섭 · 스킬 본체: [`SKILL.md`](./SKILL.md)

## 요약 아니고 회고

회고는 요약과 다르다. 요약은 "무슨 일이 있었나"에서 멈추고, 회고는 두 걸음 더 간다:

```
사실 (무슨 일)  →  성찰 (그래서 뭘 느꼈나/배웠나)  →  액션 (다음에 뭘 바꿀까)
```

이 스킬은 **거울 + 회고 틀**이다. 발화를 되비추되(사실) 성찰·액션 자리에 배치해, 사람이 마지막 10분에 회고하도록 판을 깔아준다. **알맹이는 사람이 채운다.** 빈칸 `(언급 없음)` = 아직 회고 안 한 부분.

## 스터디에서 쓰는 법

1. **발표 30분** — 각자 10분씩 챕터 정리 + 본인 생각 발표. Gemini가 회의록으로 기록.
2. **통합(merge) 끝나면** 그 회의록을 이 스킬에 투입 — "회고 돌려" / "랩업". (직전 회고가 있으면 자동으로 지난 Try 이행부터 점검)
3. 출력(지난 Try 점검 + 개인 회고 + 팀 KPT + 액션 아이템)을 화면에 띄운다.
4. **마지막 10분, 사람이 회고 토의** — `(언급 없음)` 빈칸과 확인 질문을 각자 짚으며 채운다. 회고 자체는 사람이 한다.
5. 결과 저장 → **`meeting-notes/<날짜>-<N주차>-회고.md`** (회의록 옆에 페어로).

## 출력

- **0) 지난 Try 이행 점검** — 직전 회고가 있을 때만. 지난 Try·액션이 됐나(✅/🔶/❌).
- **1) 개인 회고**(발언자별): `[사실] 핵심` · `[성찰] 내 생각·관점` · `[성찰] 걸린 것` · `[액션] 다음에`
- **2) 팀 회고 (KPT)**: `Keep` · `Problem` · `Try` ← 스터디 운영 자체
- **3) 액션 아이템**: `[ ] [담당자] 할 일 (기한)` — 다음 회고의 0)에서 이 목록을 점검
- **4) 열린 질문**: 토의서 나온 미해결 질문 (다음까지 각자 곱씹을 씨앗). 발화 기반만, AI 창작 금지
- **5) 확인 질문 1개**

## 꼭 지킬 것

- **입력은 회의록의 `📖 스크립트`(전사 발화)가 1순위.** 요약 섹션을 옮기면 "요약의 요약" = 어투가 죽는다.
- **`[성찰] 내 생각`·성찰 빈칸은 직접 채운다.** AI 안 채운다.
- **KPT는 스터디 운영** 얘기다. 챕터 지식 통합은 `chapter-merge` 몫 — 여기서 중복하지 말 것.

## chapter-merge와의 차이

- **chapter-merge**: 챕터 학습 내용을 팀 결과물로 **통합** (지식 산출물)
- **study-wrapup**: 오늘을 **회고** — 성찰·개선 (다음이 나아지게)
