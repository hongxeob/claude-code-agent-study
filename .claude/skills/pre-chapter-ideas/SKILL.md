# chapter-ideas — 챕터 → 만들 주제 추천

착수 마찰을 없애는 도구. 주제를 **정해주는 게 아니라 후보를 던진다.** 고르고 만드는 건 사람 몫.

## 입력

방금 배운 챕터의 핵심 개념 몇 줄 (붙여넣거나 `chapters/chN/README.md` 경로).

## 출력

실습 주제 후보 **4~6개**, 각 3줄:
1. 만들 것 (한 줄)
2. 이 챕터의 어떤 개념을 검증/체득하나
3. 규모 (1주차·발표 10분 안에 되나)

마지막에 **3인 분배 제안** 1줄.

## 규칙

1. 후보는 반드시 **입력한 챕터 개념에 직접** 걸리게. 챕터 무관한 일반 아이디어 금지.
2. 규모는 "만드는 데 15분~1주차, 발표 10분에 담길 것"으로 강제. 대형 파이프라인 제안 금지.
3. 각 후보에 "이걸로 **무엇을 검증/의심**해볼 수 있나" 한 줄 → 검증 사고를 심는다.
4. 후보만 던지고 고르는 건 사람에게. "정답 하나"를 밀지 마라.

## 예시

입력: "ch3에서 서브에이전트 위임과 병렬 태스크 배웠음. 뭐 만들지?"

출력(발췌):
```
- 후보 A — 레포 3폴더 동시 요약기
    members/ 세 폴더를 서브에이전트 3개로 병렬 요약.
    병렬 위임이 순차보다 실제로 빠른지·정확한지 검증.
    1주차 가능.
- 후보 B — 회의록 액션아이템 추출 서브에이전트
    meeting-notes/ 최신 회의록을 하위 에이전트에 넘겨 할 일만 추출.
    위임 시 컨텍스트가 얼마나 새는지 관찰.
    15분.
- 후보 C — "검증자" 병렬 붙이기
    아무 산출물에 리뷰 서브에이전트를 병렬로 붙여 결과 비교.
    그냥 믿을 때 vs 교차검증할 때 차이 체감.
    난이도 중.

분배 제안: A는 병렬 관심자, B는 실용파, C는 검증 담당에게.
```
