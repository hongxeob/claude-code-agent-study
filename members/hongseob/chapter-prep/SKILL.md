# chapter-prep — 챕터 정리본 → 발표 자료 (개인별)

**본인**이 자기 언어로 정리한 챕터 노트(md) → **개인 정리본 md**(확정) → 그 정리본으로 **발표 HTML 한 장**.
스터디 모이기 전 각자 돌린다. 산출물은 1인 10분 발표용.
**순차**: 깨끗한 정리본이 나와야 깨끗한 발표 자료가 나온다. 통찰은 사람이(역질문으로 확인).

## 입력

- **본인이** 정리해온 챕터 md 경로 또는 붙여넣은 텍스트.
- 챕터 번호 + 이름.
- 날것 초안을 파일로 둘 거면 루트 `_drafts/`에 `chN-<이름>-` 접두로 (gitignore됨). 커밋되는 건 정리본·발표뿐.

## 진행 (순차 — 단계마다 검증)

### 1단계 — 정리본 초안 + 역질문
- **본인** 노트를 구조화·첨삭 (여러 사람 병합 아님 — 개인별).
- **새 통찰·결론을 지어내지 않는다.** 원문 문장 보존, 중복 제거, 헤딩 부여만.
- **적용예시 실측**: 각 개념마다 내 클로드 시스템(`~/.claude/settings.json`·`skills/`·`agents/`·`rules/`·`CLAUDE.md`, 프로젝트 `.claude/`)을 **실제로 읽어** 확인된 예시 1개를 붙인다. 기억·추정으로 쓰지 마라. 시스템에 없으면 "아직 없음 + 도입한다면 어디에"로 정직히.
- 빈틈·모순인 지점은 채우지 말고 **역질문 목록**으로 뽑는다.
- 산출: `chapters/chN/<이름>/정리본.md` 초안 + 역질문 목록.

### 2단계 — 사람 게이트 (역질문) ★ 확정 전 필수
- 역질문을 **사람에게 제시** → 답 받는다.
- 답을 반영해 **정리본 확정.**
- **역질문에 사람이 답하기 전엔 3단계로 넘어가지 않는다.** (사고는 사람 몫, 발표 자료는 확정본에서만)

### 3단계 — 확정 정리본 → 발표 HTML
- **2단계에서 확정된 정리본을 입력으로** 발표 자료를 만든다 (날것 메모 아님).
- HTML 생성은 초점이 좁아 서브에이전트에 위임해도 좋다 (컨텍스트 격리).
- 자체완결 HTML **한 장** (인라인 CSS/JS, 외부 요청 0, 반응형). PPT식 넘김 금지, **하나의 스크롤 페이지**: 제목 → 핵심 개념 → 섹션별 요점 → 정리.
- **블랙박스/화이트박스 등 비교가 있으면 좌우 2열 대비로 시각화** (색/아이콘 구분).
- 산출: `chapters/chN/<이름>/발표.html`.

## 규칙

1. 정리본: 첨삭·구조화만. 통찰·평가는 역질문으로 사람에게 넘긴다.
2. 원문에 없는 사실 지어내기 금지. 빈틈은 `(확인 필요)` + 역질문.
3. 적용예시는 **파일을 읽고 확인된 것만**. 기억으로 쓰지 마라. 없으면 "아직 없음"으로.
4. HTML은 자체완결 — 외부 스크립트/폰트/이미지 요청 금지. 인라인만.
5. 블박/화박 비교는 반드시 **나란히 대비** (한쪽만 강조 금지).
6. 출력 파일 위치는 해당 `chapters/chN/<이름>/`. 덮어쓰기 전 확인.

## 산출물

- `chapters/chN/정리본.md` (사람 확인 후 확정)
- `chapters/chN/발표.html` (발표용 한 장, 브라우저로 열기)

## 블랙박스/화이트박스 시각화 예 (HTML)

좌우 2열 카드로 대비:
```
┌── 블랙박스 ──┐  ┌── 화이트박스 ──┐
│ 내부 모름     │  │ 내부 관찰      │
│ 입출력만       │  │ 단계 추적      │
└──────────────┘  └────────────────┘
```
